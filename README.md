# 共读 · PDF 阅读器

把 PDF 阅读器嵌入支持 MCP Apps 的聊天客户端。基于 MCP 官方 PDF 示例，代码与依赖固定在这个 Git 项目中。

## 已实现

- PDF.js 渲染、翻页、缩放、全文搜索、内嵌和全屏。
- 独立缩放栏：＋／－、输入 50%–300%、适合宽度、整页；手动比例在翻页和开关目录时保留，放大后可横向滚动。
- 左侧章节树、章节跳转、当前章节提示；无目录时显示说明。
- 选中文字后点击“解释选中内容”，发送文档、页码、原文与附近段落给当前聊天。
- 自动同步当前页/选区，模型也可用 `get_viewer_state` 主动读取。
- 本地 PDF 书库：选择文件导入、列表、继续阅读；原件按 SHA-256 去重保存。
- 连接本地文件夹、递归扫描 PDF、逐份或批量入库；单份失败不影响其他文件，支持停止后续入库。
- 书库资料的阅读位置、书签保存在 SQLite，重启服务或清空浏览器存储后仍可恢复。
- 打开能确定归属的文件时迁移旧指纹页码和书签；原记录保留，重复迁移不复活已删除书签。
- 选区问题带资料、版本、文件编号；批注暂时继续按 PDF 指纹保存在浏览器。
- arXiv 关键词/编号搜索、确定版本下载、进度与取消；论文入库后直接在现有阅读器打开。
- 保留官方批注、表单填写、带批注 PDF 导出与明确的保存操作。

阅读器本身不运行语言模型。解释由所在聊天的模型给出；普通浏览器测试宿主只验证消息，不生成假回答。

## 本机安装与使用

要求 Node.js 24 或更新版本、npm。本机验证版本为 Node.js 24.14.0。
书库使用 Node 内置 SQLite，不额外安装原生数据库依赖。Bun 已列入开发依赖。

```powershell
npm ci
npm run build
.\scripts\install-mcp.ps1
```

连接刷新后，点击右侧 **＋ → PDF 阅读器**，进入“我的书库”，选择本地 PDF 导入。
文件选择只上传用户选中的文件，不开放整个磁盘；当前单文件上限为 512 MB。

也可连接一个本地书库文件夹：

```powershell
.\scripts\install-mcp.ps1 -LibraryPath 'D:\Learning\Books'
```

刷新连接后，“我的书库”会显示“已连接的本地书库”。点击“扫描 PDF”，再单份或全部入库。
新增下载文件后点“重新扫描”。文件夹仅用于读取，入库复制到本机独立存储，不覆盖或删除原文件；
重复内容沿用同一份资料及阅读记录。暂不监控目录变化、不同步原文件删除、不支持 EPUB。
扫描跳过符号链接和目录联接，最多列出 1000 份 PDF / 遍历 20000 项，并显示截断或不可读项。
此功能可以读取自行下载到文件夹的 PDF，但不等于已连接在线书库账号。

默认还注册了项目自带的三页示例 PDF。若要让模型直接按路径导入自己的资料：

```powershell
.\scripts\install-mcp.ps1 -PdfPath 'D:\Learning\paper.pdf', 'D:\Learning\book.pdf'
```

连接名为 `pdf_reader`。让客户端重新加载 MCP 配置后，在聊天中说：

> 用 pdf_reader 打开示例 PDF。

选中文字后点击“解释选中内容”，或直接在聊天中问“我现在选中的内容是什么意思”。模型应继续使用原来的阅读视图，避免重复创建阅读器。

在当前 Codex 桌面版中，点击“展开阅读器”会将完整阅读器移到右侧栏，保留目录。
也可让模型对原视图调用 `interact` 的 `display_mode`，设为 `fullscreen`。
侧栏较窄时点击“目录”展开章节树。直接打开 PDF 文件预览不会带上这棵目录。

公开 HTTPS PDF 可直接让模型打开。原始学习资料继续存放在原位置；不需要复制进 AI Learning OS。

[详细接入说明](CONNECT.md) 包含当前桌面客户端、ChatGPT 网页、刷新及故障排查。`/mcp` 是协议端点，不是独立网页。

## 数据与范围

- 本地安装脚本只接受明确指定的 PDF 文件；不会自动开放客户端的整个工作目录。
- 书库资料的页码和书签在本机 SQLite；未入库 PDF 仍使用旧浏览器记录。未导出的批注仍在浏览器存储，重要批注应导出到 PDF。
- 扫描图片 PDF 可显示，但没有文字层时不能直接选词；此版不包含 OCR。
- 本地 HTTP 调试只监听 `127.0.0.1`，通过单个常驻进程运行。
- 密钥、日志、依赖和测试中间产物不纳入 Git。源码与测试夹具纳入 Git。

## 本地书库（P1）

默认数据目录为 `%LOCALAPPDATA%\GongduReader`，包含 `library.sqlite`、`blobs/` 原件、
`tmp/` 导入暂存文件和 `exports/`。可通过服务进程的 `PDF_READER_DATA_DIR` 指定其他
独立目录。不要放在 AI Learning OS、代码仓库或云盘实时同步目录中。

`documentId → versionId → assetId` 分别标识资料、确定版本和文件；`viewUUID` 仍然只
表示一次阅读窗口。本地文件导入为每份不同内容创建一个资料版本，相同 SHA-256
复用现有条目。修改过的本地 PDF 会作为新条目，不自动继承旧批注或合并成同一资料版本。
arXiv 来源则按论文编号归为同一资料，每个 `vN` 保留独立版本和文件身份。

托管原件不可覆盖。原文件移动或删除后仍可阅读书库副本；新增批注用现有导出功能保存。
成功导入前会用 PDF.js 校验文件，失败或取消不会产生书库条目。中断上传需要重新选择
文件；超过一天的遗留暂存文件在启动时清理，尚未实现断点续传或后台下载任务。

迁移只读取当前客户端可访问的、与当前 PDF 指纹一致的旧页码和书签；后端记录迁移凭证，
保留旧浏览器数据，不覆盖已经保存的阅读位置。已知同一指纹对应多个不同文件时拒绝自动
迁移。无法访问旧宿主的浏览器存储、损坏的旧记录，以及旧批注迁移，均不包含在本阶段。

阅读位置保存成功会显示“第 N 页已保存到书库”；失败显示重试入口，不会伪装成已保存。
浏览器中的旧书签不会随书库修改而改写，不能用旧版阅读器继续编辑后期待自动双向同步。

## 统一阅读上下文与引用（P2）

`src/reading-context.ts` 定义 `ReadingContext` v1。自动同步的 `structuredContent.readingContext`、
“解释选中内容”消息中的 JSON 快照，以及 `interact(get_viewer_state)` 返回的 `readingContext`
使用相同结构：资料/版本/文件身份、来源 URI、窗口、标题、PDF 文件页码、显示页码、旋转角度、
逐行选区矩形、选中文字及前后各最多 800 字上下文。矩形以旋转后的页面左上角为原点，单位为 PDF 点。
未入库 PDF 明确标记 `transient`，不凭空生成永久资料编号。

`src/host-bridge.ts` 集中调用 MCP 工具、更新上下文、发问及窗口交互；沿用 MCP Apps SDK，
不调用另一套模型 API。自动上下文按顺序发送，尚未发送的过期快照丢弃。点击解释时立即固定原文
和附近内容；后续翻页或切书不会改写该问题。消息拒绝会报错；15 秒未确认则提示先检查聊天，
不自动重发。宿主接受上下文更新仍不代表模型下一轮一定使用它，显式问题仍随消息携带完整快照。

新增 `reader_navigate({target, location})`：`target` 必须包含同一书库文件的 `documentId`、
`versionId`、`assetId` 和当前 `viewUUID`；`location` 为 `{format:"pdf", pageNumber:2}`。
服务端与阅读器都校验目标身份和页码，收到阅读器确认才返回成功。页码是从 1 开始的文件页序号，
不能把显示标签 `iv` 当成第 4 页。窗口已关闭时须先按 `assetId` 打开并取得新 `viewUUID`；
本轮只跳到引用所在页，不自动重建原文选区。旧 `interact(navigate)` 保留为普通窗口翻页。

  AppBridge 验证迁移、切书、选区引用、保存失败重试，以及空浏览器存储下的恢复。
- 已实测旧宿主支持 PDF 嵌入、目录和展开到侧栏；新版书库在当前桌面客户端刷新后的
  完整操作仍需验收。浏览器测试宿主不生成模型回答，也不代表云端部署通过。
- P2 验证：三条上下文路径一致、错误窗口/版本/文件和越界页码拒绝、真实旋转 PDF 与罗马页码、
  输入页码时重绘不覆盖输入，以及宿主拒绝/超时提示和排队上下文顺序。超时单测注入请求错误，

## arXiv 来源（P3）

从 **＋ → PDF 阅读器 → 从 arXiv 找论文** 搜索关键词、官方链接或编号。
每次返回 10 条；可用 `ti:`、`au:`、`cat:` 等查询语法。搜索结果显示明确的版本编号，
选择 `vN` 后点“下载入库”。未指定版本的编号先解析为最新的确定版本，下载任务始终固定到该版本。
下载列表显示排队、确认版本、下载、校验和完成状态；“打开论文”使用同一书库与 PDF 阅读器。

重复下载正在处理或已经入库的版本会复用原任务。取消、失败或服务重启中断后，可点“重新下载”；
本轮重新从头下载，不做断点续传。退出阅读界面不取消后台任务，回到书库可查看状态；
退出本机服务会中断任务。最多 8 个待完成任务、单文件 512 MB，串行处理；
API 请求间隔至少 3.1 秒，元数据超时 30 秒、PDF 下载超时 180 秒。限流或错误时明确报错，
不自动重复请求。使用一份本机服务进程，未提供多个进程同时调度同一书库的能力。

`arxiv.ts` 负责官方 Atom API、固定版本解析与下载任务；`arxiv-tools.ts` 提供
`arxiv_search`、`arxiv_resolve`、`arxiv_download`、`arxiv_jobs`、`arxiv_cancel`。
下载工具立即返回 `jobId`，由界面查询进度，模型不需要反复调用工具等待。
`src/arxiv-panel.ts` 提供侧栏界面；`LibraryService` 保存来源、任务与原件，PDF.js 负责文件校验。

数据库自动事务升级到 v2，保留现有资料编号、页码、书签和迁移凭证；失败会回滚。
新增 `arxiv_sources` 和 `arxiv_jobs`，原件继续按 SHA-256 保存。不同论文版本即使文件字节相同，
也保留不同 `versionId/assetId`，共用原件；书签和阅读进度不会跨版本复制。
同一版本若返回不同文件，会拒绝覆盖。引用上下文包含确定版本的官方来源链接。
旧程序不支持直接打开 v2 数据库；数据库和原件仍全部在独立书库目录，未放进代码仓库或 Obsidian。

验证范围：离线边界测试覆盖版本匹配、XML 错误、限流、下载跳转、假 PDF、不完整下载、取消/重试、
中断记录恢复、同论文版本隔离，以及 v1 数据库升级与失败回滚。侧栏测试使用模拟 arXiv 响应、
真实 MCP/SQLite/PDF/浏览器。2026-09-23 真实联网验证搜索与 `1706.03762v1` 下载（15 页），
并重启 Node 服务验证来源记录与阅读进度。未在当前 Codex 桌面连接刷新后实测新版按钮，
未做大文件压力测试或真实网络断流/进程强杀测试；中断恢复通过持久任务状态测试。

接口与请求频率依据 [arXiv API 手册](https://info.arxiv.org/help/api/user-manual.html)
及 [API 使用条款](https://info.arxiv.org/help/api/tou.html)。此阶段无需 arXiv 账号。
