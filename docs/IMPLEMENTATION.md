# 实现与验证说明

返回 [项目首页](../README.md)。本文保留各阶段的数据模型、协议、限制和验证范围；安装与连接见 [CONNECT.md](../CONNECT.md)。

## 本地书库（P1）

默认数据目录为 `%LOCALAPPDATA%\GongduReader`，包含 `library.sqlite`、`blobs/` 原件、
`tmp/` 导入暂存文件和 `exports/`。可通过服务进程的 `PDF_READER_DATA_DIR` 指定其他
独立目录。不要放在 AI Learning OS、代码仓库或云盘实时同步目录中。

`documentId → versionId → assetId` 分别标识资料、确定版本和文件；`viewUUID` 仍然只
表示一次阅读窗口。本地文件导入为每份不同内容创建一个资料版本，相同 SHA-256
复用现有条目。修改过的本地 PDF 会作为新条目，不自动继承旧批注或合并成同一资料版本。
arXiv 来源则按论文编号归为同一资料，每个 `vN` 保留独立版本和文件身份。

托管原件不可覆盖。原文件移动或删除后仍可阅读书库副本；新增批注用现有导出功能保存。
成功导入前会用 PDF.js 校验文件，失败或取消不会产生书库条目。中断上传需要重新选择
文件；超过一天的遗留暂存文件在启动时清理，本地文件导入不支持断点续传；arXiv 的后台下载见下文 P3。

迁移只读取当前客户端可访问的、与当前 PDF 指纹一致的旧页码和书签；后端记录迁移凭证，
保留旧浏览器数据，不覆盖已经保存的阅读位置。已知同一指纹对应多个不同文件时拒绝自动
迁移。无法访问旧宿主的浏览器存储、损坏的旧记录，以及旧批注迁移，均不包含在本阶段。

阅读位置保存成功会显示“第 N 页已保存到书库”；失败显示重试入口，不会伪装成已保存。
浏览器中的旧书签不会随书库修改而改写，不能用旧版阅读器继续编辑后期待自动双向同步。

## 统一阅读上下文与引用（P2）

`src/reading-context.ts` 定义 `ReadingContext` v1。自动同步的 `structuredContent.readingContext`、
“解释选中内容”消息中的 JSON 快照，以及 `interact(get_viewer_state)` 返回的 `readingContext`
使用相同结构：资料/版本/文件身份、来源 URI、窗口、标题、PDF 文件页码、显示页码、旋转角度、
逐行选区矩形、选中文字及前后各最多 800 字上下文。矩形以旋转后的页面左上角为原点，单位为 PDF 点。
未入库 PDF 明确标记 `transient`，不凭空生成永久资料编号。

`src/host-bridge.ts` 集中调用 MCP 工具、更新上下文、发问及窗口交互；沿用 MCP Apps SDK，
不调用另一套模型 API。自动上下文按顺序发送，尚未发送的过期快照丢弃。点击解释时立即固定原文
和附近内容；后续翻页或切书不会改写该问题。消息拒绝会报错；15 秒未确认则提示先检查聊天，
不自动重发。宿主接受上下文更新仍不代表模型下一轮一定使用它，显式问题仍随消息携带完整快照。

新增 `reader_navigate({target, location})`：`target` 必须包含同一书库文件的 `documentId`、
`versionId`、`assetId` 和当前 `viewUUID`；`location` 为 `{format:"pdf", pageNumber:2}`。
服务端与阅读器都校验目标身份和页码，收到阅读器确认才返回成功。页码是从 1 开始的文件页序号，
不能把显示标签 `iv` 当成第 4 页。窗口已关闭时须先按 `assetId` 打开并取得新 `viewUUID`；
本轮只跳到引用所在页，不自动重建原文选区。旧 `interact(navigate)` 保留为普通窗口翻页。


## arXiv 来源（P3）

从 **＋ → PDF 阅读器 → 从 arXiv 找论文** 搜索关键词、官方链接或编号。
每次返回 10 条；可用 `ti:`、`au:`、`cat:` 等查询语法。搜索结果显示明确的版本编号，
选择 `vN` 后点“下载入库”。未指定版本的编号先解析为最新的确定版本，下载任务始终固定到该版本。
下载列表显示排队、确认版本、下载、校验和完成状态；“打开论文”使用同一书库与 PDF 阅读器。

重复下载正在处理或已经入库的版本会复用原任务。取消、失败或服务重启中断后，可点“重新下载”；
本轮重新从头下载，不做断点续传。退出阅读界面不取消后台任务，回到书库可查看状态；
退出本机服务会中断任务。最多 8 个待完成任务、单文件 512 MB，串行处理；
API 请求间隔至少 3.1 秒，元数据超时 30 秒、PDF 下载超时 180 秒。限流或错误时明确报错，
不自动重复请求。使用一份本机服务进程，未提供多个进程同时调度同一书库的能力。

`arxiv.ts` 负责官方 Atom API、固定版本解析与下载任务；`arxiv-tools.ts` 提供
`arxiv_search`、`arxiv_resolve`、`arxiv_download`、`arxiv_jobs`、`arxiv_cancel`。
下载工具立即返回 `jobId`，由界面查询进度，模型不需要反复调用工具等待。
`src/arxiv-panel.ts` 提供侧栏界面；`LibraryService` 保存来源、任务与原件，PDF.js 负责文件校验。

数据库自动事务升级到 v2，保留现有资料编号、页码、书签和迁移凭证；失败会回滚。
新增 `arxiv_sources` 和 `arxiv_jobs`，原件继续按 SHA-256 保存。不同论文版本即使文件字节相同，
也保留不同 `versionId/assetId`，共用原件；书签和阅读进度不会跨版本复制。
同一版本若返回不同文件，会拒绝覆盖。引用上下文包含确定版本的官方来源链接。
旧程序不支持直接打开 v2 数据库；数据库和原件仍全部在独立书库目录，未放进代码仓库或 Obsidian。

验证范围：离线边界测试覆盖版本匹配、XML 错误、限流、下载跳转、假 PDF、不完整下载、取消/重试、
中断记录恢复、同论文版本隔离，以及 v1 数据库升级与失败回滚。侧栏测试使用模拟 arXiv 响应、
真实 MCP/SQLite/PDF/浏览器。2026-09-23 真实联网验证搜索与 `1706.03762v1` 下载（15 页），
并重启 Node 服务验证来源记录与阅读进度。未在当前 Codex 桌面连接刷新后实测新版按钮，
未做大文件压力测试或真实网络断流/进程强杀测试；中断恢复通过持久任务状态测试。

接口与请求频率依据 [arXiv API 手册](https://info.arxiv.org/help/api/user-manual.html)
及 [API 使用条款](https://info.arxiv.org/help/api/tou.html)。此阶段无需 arXiv 账号。

## GitHub 来源（P4）

入口：**＋ → PDF 阅读器 → 从 GitHub 找资料**。输入仓库首页链接或 `owner/repo`，可指定分支、标签或提交；
也可以搜索仓库。打开仓库时将分支解析为确定的 40 位提交，后续目录浏览、下载和引用始终使用该提交。
需要看最新版本时重新打开仓库。点击目录进入下一层，点击文件下载入库并阅读；不克隆整个仓库。

公共仓库无需账号。收藏、我的仓库和私有内容读取本机 GitHub CLI 的授权：

```powershell
gh auth login --hostname github.com --web --git-protocol https
```

在浏览器完成授权后，点击“刷新账号”，无需向聊天或阅读器粘贴令牌。已配置的 `GH_TOKEN`／`GITHUB_TOKEN`
环境变量优先于 CLI 凭据；应用不保存令牌、不读取 Codex GitHub 连接器的凭据。私有仓库要求相应的读取权限，
组织还可能要求 SSO 授权；细粒度令牌需配置目标仓库 Contents 只读权限。授权失效明确报错，不静默切换账号。
退出本机账号使用 `gh auth logout --hostname github.com`；已入库文件仍在本机保留并可离线阅读。

点击“打开仓库”后，按钮附近显示版本确认和目录读取进度，成功后滚动到目录。按钮和输入框回车直接触发读取，
不依赖嵌入窗口允许表单提交。普通 GitHub 请求超过 30 秒未返回时显示超时提示并恢复按钮；迟到的返回不会覆盖
后续操作。下载请求保留 180 秒等待，超时后先刷新书库检查是否已完成入库。

PDF 上限 100 MB，文本上限 1 MB／10000 行。仅支持 UTF-8 文本；不读取符号链接、子模块、Git LFS 实体或其他
二进制文件。下载仅请求 `api.github.com`，不跟随重定向，使用 Git blob SHA 校验内容；迁移仓库请改填新地址。
GitHub 限流、权限不足、网络超时会显示错误，用户可手动重试。

PDF 复用原阅读器。Markdown 支持排版预览和源码，代码保留行号并按行高亮；过长的行显示原始文本。
Markdown 的脚本、嵌入和图片不会加载，图片可点击“GitHub 原文”查看。外链只在用户点击时交给宿主打开。
源码模式给出所选行范围，排版模式给出所在 Markdown 段落的源文件行范围；引用不会把段落范围冒充精确字符位置。
文本支持自动上下文同步及显式选区提问；PDF 的服务端 `reader_navigate` 仍只处理 PDF 页码，文本可用行号框跳转。
文本暂不提供全文搜索、批注或书签界面。

SQLite 自动事务升级至 v3，新增 `github_sources`；旧 PDF、arXiv 阅读位置和书签保留。同一仓库路径不同提交共用
资料编号、使用独立版本与文件编号，即使字节相同也不混用阅读位置。文本在位置存储中以源文件行号保存，
PDF 仍按文件页码保存。所有原件在现有独立书库目录，源码或凭据不进入 Obsidian 知识库。

验证：GitHub API 固定样例覆盖公共／授权读取、版本隔离、旧书库升级、重启离线读取、错误凭据、重定向、
损坏／超大／二进制文件。真实 MCP＋SQLite＋浏览器覆盖 380px 侧栏中收藏→目录→Markdown／代码／PDF→
选区问答→返回书库、消息拒收提示和位置恢复。GitHub 响应在这些检查中为固定样例，不冒充真实账号验证。
最初真实公共 API 检查遭遇匿名额度限流；2026-09-28 已通过当前 MCP 连接验证登录账号，以及 `earendil-works/pi`
的提交解析和目录读取。真实收藏／私有仓库下载及当前桌面点击新按钮仍待实测。浏览器回归另覆盖不允许表单提交的
沙箱、按钮和回车、限流错误、宿主未返回时的超时恢复，以及迟到结果不覆盖新操作。

接口依据：[GitHub 仓库内容](https://docs.github.com/en/rest/repos/contents)、
[Git Trees](https://docs.github.com/en/rest/git/trees)、[Git Blobs](https://docs.github.com/en/rest/git/blobs)、
[收藏仓库](https://docs.github.com/en/rest/activity/starring)。


## 本机 OCR 与扫描页共读（2026-10-03）

扫描页点击“识别本页文字”，阅读器使用独立的无批注画布生成 PNG，经宿主工具通道交给本机 Windows.Media.Ocr。
不使用聊天模型的图像识别，也不下载模型。当前要求 Windows 10/11 已安装 OCR 语言组件；其他系统或语言缺失会说明原因。
“识别设置”可选择已安装语言及文字方向；方向只用于识别，不修改 PDF 原件。识别结果可展开核对，并可切回原文字层。

页面 PNG 最长边以 2600 像素为目标，最大渲染倍率 3.5；服务边界拒绝非 PNG、超过 8 MB、单边 4096 像素或总像素 1600 万的输入。
服务串行识别，每项任务最长 60 秒，最多保留八项结果、五分钟到期；页面图片和结果不写入书库原件。
Windows 子进程固定执行识别脚本，输入通过标准输入 JSON 传递，不接受任意命令或文件路径。

工具 `reader_ocr_capabilities/start/status/cancel` 仅对应用界面可见。该可见性是宿主路由约束，不等于操作系统网络隔离；
OCR 引擎本身由本机 Windows 运行，PNG 仍会经过承载阅读器的 MCP 宿主和工具通道。
当前部署与验证均为本机服务，不把这一实现描述成适用于任意远程宿主的离线保证。

识别结果根据单词坐标覆盖到 PDF 页，按返回行序保留文字；不推断复杂表格或多栏的语义阅读顺序。
OCR 选择的邻近内容只取同一识别行；跨行选择明确标记邻近内容不可用。复制和发问保留单词边界。
引用的 `textSource` 包含引擎、语言、结果 ID 和 `verified:false`，问题提示区分 OCR 与已核对原文，公式、表格和疑似错字保留不确定性。

识别成功后的自动上下文只更新资料、页码和 OCR 来源，不自动发送识别全文、选区或截图。
用户点击解释、学习操作或模型显式读取时才传递对应文字；`interact(get_text)` 可读取本阅读窗口缓存的 OCR 页，并带未经核对标记。
前端只缓存最近八页；重新打开文件后需再次识别。换页、切书、切回原文字层与关闭都会作废旧任务；迟到结果不能覆盖新页。

## 阅读操作与笔记（2026-10-03）

- PageDown／空格先向下移动约一屏，到底再翻页；PageUp／Shift＋空格反向执行。左右方向键与翻页按钮直接换页。
  前翻从上页底部接读，其他跳页回到页首；横向触控板手势在一段连续滚动中至多翻一页。输入框保留自身键盘操作。
- “专注阅读”收起学习区、OCR 与缩放栏，保留基本阅读导航和选区提问。选区动作出现时不得改变正文位置。
- 书库支持多份 PDF 拖入／选择、逐份进度、停止队列和独立失败提示；已入库文件不会因后续文件失败而撤销。
  队列完成不自动替换当前正在读的资料。文件内容去重沿用书库 SHA-256 身份，书库可按名称查找及按阅读／加入时间或书名排序。
- 学习记录默认只显示当前资料，可切全部资料、搜索原文和笔记，导出当前可见记录的 Markdown。
  导出保留资料身份、版本、来源、页／行、原文、自己的笔记、OCR 未核对标记与保存状态；尚未保存的当前草稿也会带出。
- 没有选区也可以记录本页笔记；“提问检验”先问一个问题并等待学习者回答。
  “检验我的理解”把自己的文字与固定原文作为独立记录发送，要求区分学习者表述和 AI 纠正；不覆盖原笔记，不把请求已送达当成学习完成。
- 笔记继续使用浏览器本地存储和跨窗口 Web Locks；编辑基线冲突时保留草稿并拒绝覆盖。离开前提示尚未保存的修改。
  没有数据库笔记同步或跨客户端恢复，需主动保存及导出。
- 单条记录删除使用行内确认，默认聚焦“取消”，Esc 可退出；有未保存草稿或状态时明确告知一并丢弃，只删除本机学习记录，不影响原文与聊天消息。
  确认时固定原保存基线，在同一个 Web Lock 中重读存储并仅移除目标记录，保留其他窗口的新增记录；并发修改／删除或写入失败时保留当前记录、草稿和错误说明。
  本窗口发送 AI 请求时禁用删除，同条记录的保存与删除互斥；另一窗口在请求期间删除后，迟到回执不会重新创建存储记录，本窗口仍保留可导出的回执和草稿。
  删除成功后清理该条记录的草稿、未保存状态和离开提醒，筛选数量与导出内容随即更新。

外观提供中性、樱花、晴空、抹茶、可可五种界面配色，各自适配浅色和深色；PDF 原稿颜色保持原样。
可独立开关阅读进度与专注计时，界面隐藏或离开资料时暂停计时。页数、时长只代表阅读位置和时间，不计作学习掌握程度。

验证使用真实 Chromium、MCP AppBridge、SQLite、PDF.js 和本机 Windows OCR，合成扫描 PDF 覆盖重复英文行的实际鼠标选择、
纯文本发送、来源一致性、识别方向调整、缩放缓存、换页取消及窄屏专注布局。笔记检查覆盖筛选中编辑再导出和多窗口冲突，
导入检查覆盖多文件、去重、失败和取消。另用已安装的简体中文引擎识别清晰宋体扫描样例，57 个字符与源文字一致；不将该结果推广到真实旧书、复杂版式或公式。原有阅读、GitHub 与 stdio 回归按受影响范围执行。
这些证据不等于 Codex 原生侧栏已加载本轮新服务，也不证明实际模型已经正确回答；原生新版本加载仍需客户端连接恢复后实测。

## 旋转与裁剪 PDF 的坐标（2026-10-03）

批注、原文选择、搜索高亮、图片放置与模型坐标现在统一通过 PDF.js PageViewport 转换，包含原文件的 Rotate、CropBox 与 UserUnit。批注自身角度保留在 PDF 原始坐标中，再跟随页面显示方向；截图和导出使用同一几何约定。
